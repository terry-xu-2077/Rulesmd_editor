# Rulesmd Editor 工作区 UI 约定

本文记录当前主工作区的固定交互与视觉规则，避免后续迭代重新引入已经淘汰的布局。

## 顶部应用栏

- 左侧品牌使用旧 `RulesmdEditorWeb/img/appIcon/资源 1@64x-8.png`，开发启动器同步为 `frontend/public/legacy/app-logo.png`。
- 新建、打开、保存、启动游戏、设置使用“图标 + 名称”，整组在窗口顶部水平居中；不要再次靠左堆在品牌旁。
- 右侧仅保留必要的保存状态，不在底部重复显示编码、CRLF、参数数量、Ares 等低价值状态。

## 启动器图标生成

`src-tauri/app-icon.png` 是 Tauri 应用图标源。启动器计算其 SHA256，并把指纹保存在被 Git 忽略的 `frontend/node_modules/.rulesmd-icon-source.sha256`。

只有以下情况才执行 `tauri icon`：

1. 源 PNG 指纹变化；或
2. 生成产物 `src-tauri/icons/icon.ico` 缺失。

普通启动禁止每次重复生成整套 Windows/macOS/iOS/Android 图标。

## 参数区与历史导航

- 当前对象渐变 Header 只显示对象信息。
- 引用浏览历史放在参数工具区第一行中间。
- 历史按钮是紧凑的双段胶囊，不占据中央大面积宽度；手动选择单位会重置历史，引用跳转才继续追加。
- 参数分类位于工具区第二行，并使用独立圆角 Tag；允许自然换行，工具区高度跟随内容增长，禁止分类与第一行控件互相覆盖。

## 表格 / 原文

- 原文不再放在右侧帮助栏底部。
- 右上角提供 `表格 / 原文` 两态切换。
- `表格` 显示高密度 Key / 参数名 / 值编辑器。
- `原文` 在中央主工作区显示当前 Section 的真实 INI 文本。
- 右侧参数帮助在两种视图中都保持可用。

## 右侧帮助层级

右侧是用户反复阅读的上下文区域：

1. 参数中文说明是第一视觉层，使用明确但克制的圆角说明卡片与略高亮文字。
2. Key、控件类型、当前值、值类型、来源等元数据仅作为辅助信息，禁止使用亮色大卡片抢占注意力。
3. 右侧允许鼠标滚轮滚动超长帮助，但不显示纵向滚动条。

## 滚动条

参考旧 Web `css/public.css`：

- 滚动轨道使用低透明蓝色背景。
- Thumb 使用圆角灰色渐变。
- 当前桌面版宽度收敛到 10px，避免旧 Web 14px 在高密度桌面布局中过重。
- 对象树、参数表、原文、弹窗列表使用同一套规则；右侧帮助栏隐藏 scrollbar。

## 亮色 / 暗色

外观设置必须作用于整个 `.app`，不能只改变 UI Library 弹窗。

亮色模式采用蓝灰层级：

- 页面背景最浅；
- 面板/表格行/控件逐层加深；
- Accent/Effect 只用于选中、焦点和少量强调；
- 禁止大面积高饱和青色或纯白文本造成刺眼。

`跟随系统` 在渲染时读取 `prefers-color-scheme`，并把最终解析出的 `light/dark` 传给整套应用主题。

## BoolSwitch

BoolSwitch 是 UI Library 通用组件，Rulesmd Editor 不允许用业务 CSS 修其内部几何。

组件必须加载 `bool-switch.css`，使用专用 `.tc-bool-wrap`，固定短宽度，并覆盖旧 `theme.css` 中历史遗留的 `90px / left:126px` 几何。任何父容器只能决定开关的位置，不能拉伸开关内部 Track/Knob。
