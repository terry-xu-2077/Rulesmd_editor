# Rulesmd Editor 工作区 UI 约定

本文记录当前主工作区的固定交互与视觉规则，避免后续迭代重新引入已经淘汰的布局。

## 顶部应用栏

- 左侧品牌使用旧 `RulesmdEditorWeb/img/appIcon/资源 1@64x-8.png`，开发启动器同步为 `frontend/public/legacy/app-logo.png`。
- 新建、打开、保存、启动游戏、设置使用“图标 + 名称”，整组在窗口顶部水平居中；按钮宽度必须按“图标 + 名称”内容自适应，禁止再次固定为仅图标宽度导致文字互相覆盖。
- 右上角只保留 `表格 / 原文` 两态切换；保存状态不单独占一块区域。有未保存修改时，仅在“保存”文字后显示一个亮色小点。
- 窗口不足以容纳完整文字按钮时才退回纯图标布局，且右侧视图切换仍保持独立对齐。

## 启动器图标生成

`src-tauri/app-icon.png` 是 Tauri 应用图标源。启动器计算其 SHA256，并把指纹保存在被 Git 忽略的 `frontend/node_modules/.rulesmd-icon-source.sha256`。

只有以下情况才执行 `tauri icon`：

1. 源 PNG 指纹变化；或
2. 生成产物 `src-tauri/icons/icon.ico` 缺失。

普通启动禁止每次重复生成整套 Windows/macOS/iOS/Android 图标。

## 参数区与历史导航

- 当前对象渐变 Header 只显示对象信息。
- 引用浏览历史放在参数工具区第一行中间。
- 历史按钮是紧凑的双段胶囊，不占据中央大面积宽度；手动选择单位会重置历史，引用跳转才继续追加。
- 参数分类位于工具区第二行，并使用独立圆角 Tag；允许自然换行，工具区高度跟随内容增长，禁止分类与第一行控件互相覆盖。
- 亮色模式下历史导航必须使用独立的浅色浮雕配色，禁止直接复用暗色胶囊。

## 参数控件尺寸与多选

- 旧 Web 的通用控件参考尺寸是 `220×26px`，当前 Rulesmd Editor 为提高主表空间利用率，业务值列统一采用 **180px** 编辑槽。
- `TextField / Select / MultiSelect / Slider / BoolSwitch` 在参数表中占用同一 180px 槽；引用跳转按钮位于槽外固定位置。
- 设置窗口等普通场景的 `BoolSwitch` 仍使用 UI Library 默认短尺寸；表格场景只通过 UI Library 暴露的 `--tc-bool-width` 覆盖总宽度，业务 CSS 不再自行计算 Track/Knob 的运动逻辑。
- `BoolSwitch` 的 Track/Knob 几何在暗色和亮色下必须完全一致；主题只能改变颜色，不能改变比例、位置、行程或 relief 方向。
- `BoolSwitch` Knob 以 Track 的真实垂直中心线定位，禁止使用 `top:0` 造成肉眼可见的上偏。
- `BoolSwitch` ON 端位必须移动到轨道右端，不再保留旧 Web 的额外 4px 末端空隙。
- `BoolSwitch` 的 Track 内部必须保留一条独立的内凹滑槽，滑块在滑槽上移动；不能只剩平坦背景。
- `Slider` 仍然占满 180px 槽；thumb 使用轻微纵向渐变，并使用严格居中的 **2×3** 防滑点阵。
- Select / 搜索 Select 的关闭态文字必须在控件高度内严格垂直居中；弹层必须覆盖后续表格行和跳转按钮。候选项背景必须填满弹层宽度，不得按文字长度形成长短不一的条目。
- 多选弹出菜单不受 180px 关闭态限制，可以扩展到更宽区域以展示候选项。
- `MultiSelect` 的候选项支持可选图标。国家使用旧 Web `countryTile.png`（每格 60×40，两排五列），单位/建筑使用 `iconTile.jpg`；有图标时显示“图标 + 中文名”，无可用图标时自然退化为文字。
- 多选关闭态只有在**实际发生文本截断**（`scrollWidth > clientWidth`）时才显示完整内容气泡。该气泡仅用于补全被截断的当前值，不得显示参数注释或帮助说明，也不得在内容完整可见时出现。

## 添加参数过滤与浏览器

- 添加参数窗口默认开启“参数过滤”，但不向普通用户展示“安全过滤”等提示文案；过滤属于编辑器的静默保护。
- 高阶用户可以关闭“参数过滤”，此时显示规则库中所有尚未存在于当前 Section 的参数。关闭过滤只影响参数浏览器，不改变解析、保存或 Ares 开关语义。
- YR 原版兼容性按以下优先级判断：
  1. `yr_applicability.py` 中根据 ModEnc / DeeZire 的 Yuri's Revenge `Applicable INI Flags` 与单参数 `Applicable to` 整理出的高置信对象类型；
  2. 旧 `HelpInfor.ini` 中出现“仅用于 / 只能用于 / 只能用在 / 适用于”等明确限制语句时进行保守推断；
  3. 没有明确元数据时，只参考当前打开 rulesmd 中**同一精确对象类型**真实出现过的 Key，禁止再把全部 TechnoType 混在一起作为兜底。
- `HelpInfor.ini` 的值级说明不得错误提升为整个 Key 的对象限制；只有 Key 级明确限制才用于过滤。
- Ares 继续使用独立 `ares_schema.json` 的 `applies_to` 与官方文档元数据，不与 YR 过滤数据混存。
- 参数浏览器中间列表只承担选择职责，只显示“中文参数名 + Key + 必要来源徽标”；参数注释和详细说明只显示在右侧详情区，禁止重复塞回中间列表。
- 参数浏览器必须完整跟随应用亮/暗模式，包括搜索栏、过滤开关、分类树、中间列表、右侧详情、滚动条与底部操作区。

## 对象树阵营分类

- 左侧对象树按阵营组织，不再按国家拆分。
- 阵营判定禁止依赖 Section ID 前缀猜测作为主逻辑：先从国家 Section 的 `Side=` 建立国家→阵营映射，再用单位/建筑的 `Owner=`，缺失时参考 `RequiredHouses=`。
- 所有国家属于同一阵营时归入该阵营；跨阵营或无法判断时才进入“其他/中立”。
- 原版十国映射仅作为缺少国家 `Side=` 时的兼容回退；模组自定义国家应优先服从自身 `Side=`。
- 亮色模式下对象名称和 Section ID 必须保持足够对比度，禁止出现接近背景色导致单位名称不可读。

## 表格 / 原文

- 原文不再放在右侧帮助栏底部。
- 右上角提供 `表格 / 原文` 两态切换。
- `表格` 显示高密度 Key / 参数名 / 值编辑器。
- `原文` 在中央主工作区显示当前 Section 的真实 INI 文本。
- 右侧参数帮助在两种视图中都保持可用。

## 参数表层级与分类过滤

- 分类折叠栏必须明显比普通参数行更深，使用深蓝黑渐变、轻微顶部高光和底部暗边来形成结构层级。
- 当前选中参数行应比普通 hover 更明显：左侧 4px 焦点线 + 更明显但克制的蓝青混合底色 + 轻微悬浮阴影。
- 选中行仍不得使用大面积高饱和纯色，避免破坏长时间编辑时的视觉舒适度。
- 当顶部分类 Tag 选择某个具体分类时，该分类在“独显”状态下必须**临时强制展开**，无视之前的折叠状态。
- 临时强制展开不得修改用户在“全部”视图下保存的折叠记忆；切回“全部”后恢复原有折叠状态。
- 在具体分类独显状态下点击分类折叠栏不得改写原有折叠记忆。

## 右侧帮助层级

右侧是用户反复阅读的上下文区域：

1. 参数中文说明是第一视觉层，使用明确但克制的圆角说明卡片与略高亮文字。
2. Key、控件类型、当前值、值类型、来源等元数据仅作为辅助信息，禁止使用亮色大卡片抢占注意力。
3. 右侧允许鼠标滚轮滚动超长帮助，但不显示纵向滚动条。
4. 参数说明只在右侧帮助区域展示；不得借用通用控件 Tooltip 重复显示说明。

## 滚动条

参考旧 Web `css/public.css`：

- 滚动轨道使用低透明蓝色背景。
- Thumb 使用圆角灰色渐变。
- 当前桌面版宽度收敛到 10px，避免旧 Web 14px 在高密度桌面布局中过重。
- 对象树、参数表、原文、弹窗列表使用同一套规则；右侧帮助栏隐藏 scrollbar。

## 亮色 / 暗色与颜色延展

外观设置必须作用于整个 `.app`，不能只改变 UI Library 弹窗。

主题继续只暴露五个公共通道：`Base / Accent / Effect / Text / Text Bright`，派生色角色必须明确：

- `Base` 与中性钢蓝形成 page / surface / panel / control-fill 层级；
- `Accent` 主要用于选中、开关、菜单打开等交互状态；
- `Effect` 主要用于焦点、边缘强调和有限光效；
- 正文使用 `Text`；暗色模式下编辑框、下拉菜单和数值控件的主要内容统一使用白色 `Text`；
- `Text Bright` 只保留给真正需要强调的值或状态。

亮色模式采用蓝灰层级：页面背景最浅，面板/表格行/控件逐层加深；Accent/Effect 只用于选中、焦点和少量强调，禁止大面积高饱和青色。所有弹窗、对象树、导航、参数浏览器和 UI Library 控件都必须参与同一主题切换，禁止出现“主界面亮色但弹窗仍暗色”的混合状态。

`跟随系统` 在渲染时读取 `prefers-color-scheme`，并把最终解析出的 `light/dark` 传给整套应用主题。

## BoolSwitch

BoolSwitch 是 UI Library 通用组件。默认短形态、可变总宽度、Track/Knob 比例、两态移动、内凹滑槽与对向浮雕渐变都由 `bool-switch.css` 统一管理。

Rulesmd Editor 只负责在参数表提供 `--tc-bool-width:180px`，设置页保持 UI Library 默认的 78px。设置页的 260px 右侧布局列只负责摆放位置，不允许拉伸 BoolSwitch 本体。禁止再次在业务层复制一套 BoolSwitch 组件或重新实现其内部状态几何。
