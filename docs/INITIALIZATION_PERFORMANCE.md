# 打开 / 新建文档初始化性能规则

Rulesmd Editor 的初始化目标是：**用户选择或新建 INI 后，只等待“立即显示编辑界面”所必需的数据；参数目录、候选菜单等可延后工作必须后台预热或按需生成。**

## 临界路径

打开 / 新建文档同步阶段只允许包含：

1. 文件读取、编码识别与无损解析；
2. 建立文档结构索引（Section、line id、Section 范围）；
3. 建立编辑当前文档必须使用的基础索引；
4. 生成对象树所需的轻量 snapshot；
5. 载入首个可见 Section。

不得把“用户稍后才可能使用”的工作塞进这条路径。

## 必须延后或后台执行

以下工作默认不应阻塞打开 / 新建：

- “添加参数”窗口的 YR + Ares 全量参数目录合并、排序与预热；
- 大型候选列表的二次整理；
- 与当前首屏无关的预计算；
- 可由缓存复用的展示层目录生成。

当前实现中，Python sidecar 使用后台 worker 预热统一参数目录；前端模块加载时会异步启动 Python backend，使 schema 初始化尽量发生在用户选择文件之前。

## 算法红线

**禁止用多线程掩盖 O(n²) 初始化。**

先消除重复全文件扫描，再考虑线程化。`IniDocument` 必须维护结构索引；Section 查找、line-id 查找、Section 边界查找不得每次重新遍历整个 `rulesmd.ini`。

结构修改后必须刷新结构索引；只修改已有值时不得无意义重建结构索引。

## 并发边界

文档本体仍由主 workspace 串行修改，以保证：

- line id 稳定；
- duplicate key 行为稳定；
- dirty/baseline 正确；
- 保存结果与 UI 一致。

后台线程当前只做**只读、可丢弃、可重算**的预热工作，不得直接修改 `IniDocument`。

如果以后把更多索引放到后台线程，必须先在私有临时结构中构建完成，再通过 generation/version 检查一次性替换；旧文档的后台结果绝不能覆盖新打开的文档。

## UX 原则

“忙碌”状态只表示用户当前确实不能继续操作的短临界阶段。参数目录尚未预热完成不应让整个编辑器保持 busy；如果用户极快地打开参数窗口，则该窗口自己等待该数据即可。
