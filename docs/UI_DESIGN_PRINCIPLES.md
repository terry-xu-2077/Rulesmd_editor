# UI 设计原则

本项目的 UI 调整默认遵循以下硬性原则。除非某个界面有明确、可说明的设计目的，否则不得偏离。

## 1. 容器内默认双向居中

一个控件、图标、文字块或操作区被放进一个明确容器后，如无特殊要求：

- 水平方向按该容器的布局规则对齐；独立内容默认居中。
- 垂直方向默认居中。
- 不允许出现“同一行中某个控件贴顶/贴底、其它控件居中”的随意布局。
- 两列布局中，第二列的控件组同样需要在自身列内垂直居中。

只有在信息层级、基线对齐、表格行、正文排版等场景确有理由时，才允许显式改为顶部/底部对齐。

## 2. 同类控件必须复用同一视觉和交互

- 已有 UI 库组件能够覆盖的场景，优先直接使用 UI 库组件。
- 不为同一种“单选下拉”“多选下拉”“按钮”“开关”等控件在业务页面重新造一套样式。
- 同类控件的高度、圆角、边框、内边距、字体、箭头、悬停、焦点和禁用态必须一致。
- 业务页面只负责布局和业务语义，不复制 UI 库内部样式。

## 3. 弹出层必须根据可用空间自动选择方向

所有下拉菜单、选择器、悬浮列表等弹出层：

- 默认向下展开。
- 打开前检查视口/滚动容器的可用空间。
- 下方空间不足而上方更充足时，自动改为向上展开。
- 不允许菜单被窗口、表格滚动区或对话框边界截断。
- 弹出层应与触发控件正确对齐，并保持合理的最小边距。

该行为应优先在 Terry React UI Library 的通用组件中实现，而不是每个业务页面分别补丁。

## 4. 信息密度优先，但不能牺牲层级

- 能合并为一行两列的区域，不应拆成两条占满宽度的行。
- 无实际信息价值的标题、栏头、装饰区应删除，例如仅写“对象”但没有额外语义的独立标题行。
- 压缩空间时必须保持清楚的分组、留白和视觉层级，不能只靠缩小间距。

## 5. 图标与状态来源必须唯一

- 同一对象在左侧树和编辑区显示的图标，应来自同一个状态/解析函数。
- 禁止通过 DOM 查询、DOM 复制、MutationObserver 等方式同步业务状态。
- React 界面使用 state/props 传递对象状态；图标、名称、阵营等均从同一对象模型直接渲染。

## 6. 主题颜色必须完整覆盖

用户自定义主题色后：

- 主背景、次级背景、面板、表格、侧栏、对话框、输入区等应由统一主题变量派生。
- 不应残留与当前主题无关的硬编码墨蓝/深灰底色。
- 特殊强调色可以独立存在，但基础表面颜色必须跟随主题。

## 7. 默认原则

当没有额外设计说明时，优先采用：

1. 对齐清楚；
2. 容器内垂直居中；
3. 同类控件一致；
4. 空间紧凑但层级明确；
5. 自动避免弹出层溢出；
6. 状态来源唯一；
7. 不以临时 DOM 补丁代替组件/状态设计。
